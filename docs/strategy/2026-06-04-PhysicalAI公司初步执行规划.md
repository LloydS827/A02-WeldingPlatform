# Physical AI 公司初步执行规划

日期：2026-06-04

## 1. 执行定位

这份文件承接顶层战略，但不重复定义公司。它回答的是：在当前「焊接技能大师平台」已经形成若干证据链的基础上，如何把研发推进收束到 Physical AI for Welding 的战略验证路径上。

当前阶段不宜追求大而全的平台，也不宜直接跳到完整真机闭环。更合理的启动方式，是围绕少数焊接任务族，把“任务知识、仿真/样本、技能包、机器人执行基线、证据报告”这一条链路做扎实。

## 2. 大的推进节奏

推进节奏不需要先按月份拆计划，而应按问题成熟度推进。

第一步是收敛。基于当前资料底座和 synthetic v2 输入规范，选出少数最适合启动的任务族，明确哪些字段有来源，哪些仍是假设，哪些必须等待真实验证。这个阶段的重点不是生成大量样本，而是把任务边界和证据边界定清楚。

第二步是打通。围绕选定任务族，把仿真输出或样本结果稳定接入 `SkillDataset`，形成可复用的 `WeldSkillPackage`，并输出机器人程序、轨迹或调试输入的原型基线。这个阶段的重点不是追求高保真仿真，而是证明平台能持续接住数据、形成技能资产并进入执行端。

第三步是验证。引入专家复核、有限真机数据或客户现场资料，对技能包的适用范围、失败边界和证据链进行校准。这个阶段才开始讨论哪些能力可以进入真实工艺和生产试验，哪些仍停留在仿真或研究状态。

## 3. 当前项目如何承接

当前项目已经具备几个可继续推进的基础：

- 经验结构化 POC：证明轨迹和动作经验可以被拆解、重组和评估；
- 技能迁移 MVP：证明样本可以形成 `WeldSkillPackage` 并迁移到相近条件；
- 资料底座 gate：证明资料来源、字段覆盖和任务证据可以被 manifest-first 管理；
- `SyntheticSkillDataset v2` 输入规范 gate：证明仿真输入可以被任务、字段和证据约束；
- `SimulationOutputBundle` 导入 gate：证明仿真输出可以进入平台数据层并生成证据报告。

这些能力不应被当成散点功能。它们应收束为一条主线：

> 任务族选择 -> 输入规范 -> 仿真/样本输出 -> `SkillDataset` -> `WeldSkillPackage` -> 机器人执行基线 -> 证据报告

下一步研发应优先补强这条主线，而不是另开过多方向。

## 4. 启动策略

启动策略应保持轻、窄、可验证。

先选一个到两个最适合的焊接任务族作为样板任务。优先选择公开资料较充分、轨迹形态相对简单、机器人执行关联明确、质量结论边界容易说明的任务，而不是从最复杂的空间曲线、立焊仰焊或熔池闭环开始。

围绕样板任务，先形成一套内部可复盘的技能资产样本：包括任务定义、字段来源、仿真假设、样本数据、迁移规则、机器人执行基线、失败边界和证据报告。这个样本不需要一开始对外包装，但必须经得起内部技术和工艺讨论。

外部仿真器、机器人品牌、Rerun 可视化和大模型能力都按 adapter 处理。它们可以增强系统，但不能替代核心 schema、gate、技能包和证据链。

## 5. 关键问题

当前最重要的问题不是“还能加什么功能”，而是以下几件事是否被回答清楚。

第一，启动任务族是否足够窄。任务太散，技能包无法复用；任务过难，会被传感、控制和现场不确定性拖住。

第二，`WeldSkillPackage` 的最小定义是否稳定。它必须足够小，能被当前项目生成；也必须足够完整，能承载后续迁移、执行和审计。

第三，仿真和真实质量的边界是否清楚。仿真可以用于样本、规则和边界探索，但不能被写成真实焊接质量验证，也不能替代 WPS/PQR。

第四，机器人执行层的最小形态是什么。当前更适合输出机器人程序、轨迹或调试输入的原型基线，而不是承诺现场稳定闭环。

第五，客户验证应验证什么。早期客户沟通不应只问是否愿意买 AI，而应验证他们是否认同“把焊接技能从个人经验变成组织资产”这个问题，以及他们愿意提供哪些任务、专家和数据来共同校准。

## 6. 不进入当前主线的事项

为了避免过早发散，当前不把以下事项作为主线：

- 不以机器人本体、焊机硬件或现场系统集成为核心；
- 不以完整 ManiSkill/Isaac 集成为阶段目标；
- 不以熔池视觉闭环、焊中闭环控制或高保真熔池物理仿真作为启动点；
- 不把公开资料或仿真结果写成真实质量结论；
- 不生成或替代 WPS/PQR；
- 不为了展示效果增加与技能资产沉淀无关的 demo。

这些方向并非都没有价值，而是暂时不应挤占主线。

## 7. 阶段性判断

当前项目已经不是纯想法，它已经具备战略原型的骨架。但它也还不是可生产交付的 Physical AI 产品。

下一步最重要的动作，是用少数样板任务证明一件事：焊接技能可以被持续地组织成数据、技能包、执行基线和证据链。

只要这件事成立，公司方向就会从“概念判断”进入“可验证路线”。后续所有研发、客户沟通和资源投入，都应围绕这条路线推进。
