# 下一阶段场景仿真与接入计划

日期：2026-06-04

## 1. 计划定位

本计划用于把「焊接技能大师平台」从上一阶段的 schema、gate 和报告能力，收束到下一阶段的核心任务：选定一个具体焊接场景，围绕该场景完成资料补强、仿真样本设计、仿真输出接入和技能资产样板闭环。

它不是完整产品路线，也不是公司级 BP。它只回答当前项目下一步应该做什么，以及为什么这样做能服务于 Physical AI for Welding 的整体目标。

## 2. 下一阶段目标

下一阶段的目标是形成一条可复盘的样板链路：

> 场景选择 -> 资料补强 -> 仿真输入定义 -> 仿真输出接入 -> `SkillDataset` -> `WeldSkillPackage` -> 执行基线 -> 证据报告

这条链路的意义不是证明真实焊接质量已经成立，而是证明平台能围绕一个真实工业场景，把工艺知识、仿真数据、技能资产、执行边界和证据管理组织起来。

如果这条链路跑通，项目就从“多个能力点已经完成”进入“围绕公司核心目标形成样板能力”的阶段。

## 3. 推荐起始场景

下一阶段建议优先锁定：

> 船舶加筋板 / 纵骨角焊场景，内部标识为 `stiffened-panel-fillet`。

选择它的原因是：

- 它属于船舶制造中的典型焊接任务，和项目现有资料底座匹配；
- 它与机器人焊接设备和生产线自动化高度相关；
- 它的轨迹形态相对清晰，适合先做仿真输入和输出接入；
- 它能体现技能资产价值：任务、姿态、轨迹、速度、角度、参数假设和证据边界都可以被结构化；
- 它比立焊、仰焊、复杂空间曲线或熔池闭环更适合作为启动样板。

`panel-butt` 可作为第二候选，用于后续对照；`micro-panel-web-bulkhead` 暂时保留为复杂任务储备，不作为第一条主线。

## 4. 需要继续积累的技术内容

### 4.1 场景定义

围绕 `stiffened-panel-fillet`，需要把场景定义收敛到可计算、可生成、可验证的程度：

- 工件对象：加筋板、纵骨、面板线或相近结构；
- 焊缝类型：角焊缝；
- 姿态边界：优先从平焊或近似平焊开始；
- 轨迹边界：优先长直线或可分段近似直线；
- 工艺字段：焊枪角度、行走速度、焊脚尺寸、板厚、电流电压占位、适用边界；
- 输出对象：轨迹、姿态、过程信号、assumption、artifact refs、evidence bindings。

### 4.2 仿真输入与输出

当前项目已经有 input-spec gate 和 simulation ingest gate。下一步应补强的是两者之间的样板设计：

- 从 ready 任务族生成一个更完整的 `SimulationInputSpec`；
- 明确哪些字段来自公开资料，哪些字段是假设，哪些字段必须后续真实验证；
- 用 simlite 先生成稳定、可测试、可复现的样板 bundle；
- 保持 ManiSkill / Isaac / SAPIEN 为外部 adapter 评估方向，不把它们变成当前主路径依赖；
- 将输出 bundle 导入 `SkillDataset`，并保留 `input_id`、`taxonomy_ref`、`simulation_run_id`、assumption 和 evidence。

### 4.3 技能资产样板

下一阶段应形成一个围绕 `stiffened-panel-fillet` 的最小 `WeldSkillPackage` 样板。

这个样板至少要说明：

- 这个技能来自哪个任务族和哪些资料约束；
- 轨迹、姿态和参数如何被组织；
- 哪些内容是仿真或公开资料假设；
- 哪些内容不能用于真实质量结论；
- 迁移或复用只允许发生在什么边界内；
- 能输出什么机器人执行基线或调试输入。

### 4.4 证据报告

报告不应只是运行结果记录，而要回答工业客户和内部团队最关心的问题：

- 为什么选择这个场景；
- 资料是否足以支撑当前仿真设计；
- 仿真输出是否符合平台 schema；
- 技能包是否保留了来源、假设和边界；
- 这个样板还缺哪些真实验证。

## 5. 需要继续查询和整理的资料

下一阶段不需要泛泛增加资料，而要围绕 `stiffened-panel-fillet` 补齐最小资料闭环。

优先查询和整理：

1. 船舶面板线、加筋板、纵骨焊接的公开工艺说明和设备案例；
2. 面板线焊接机器人、龙门焊接设备、自动角焊设备的任务描述；
3. 角焊缝相关的公开工艺变量说明，如焊枪角度、行走速度、焊脚尺寸、电流电压变量边界；
4. 公开可引用的 GMAW / FCAW 通用过程资料，用于字段定义和假设标注；
5. 与机器人轨迹、姿态、示教、离线编程相关的公开资料，用于执行基线表达；
6. 公开数据集中的过程信号字段参考，用于确定 `process_signals.csv` 的最小字段集合；
7. WPS/PQR、船级社或质量验证相关的边界资料，只用于说明不能替代正式工艺评定。

这些资料进入项目时必须继续遵守 manifest-first 方式：先登记来源、用途和边界，再进入字段覆盖或任务证据，不直接写成真实质量结论。

## 6. 项目应该怎么做

下一阶段建议按四个动作推进。

第一，锁定场景。把 `stiffened-panel-fillet` 从 ready 任务族提升为当前样板场景，明确它是下一阶段主线，其他 ready 任务暂时只作为备选。

第二，补齐资料。围绕该场景补 source card、field coverage 和 task evidence。新增资料只服务于场景、字段和边界，不做无目标资料堆积。

第三，做仿真样板。先用 simlite 生成一组可复现的 `SimulationOutputBundle`，验证从输入规范到输出接入的链路。外部仿真器只做 adapter 评估，不阻塞主线。

第四，形成技能资产样板。把导入后的样本组织成 `WeldSkillPackage`，输出执行基线和证据报告，明确哪些能力已经由软件和数据结构验证，哪些仍需专家或真机验证。

## 7. 不做事项

下一阶段暂不做以下事项：

- 不进入泛化多场景大规模样本生成；
- 不追求完整 ManiSkill/Isaac 集成；
- 不做熔池视觉、熔池控制或焊中闭环；
- 不把仿真结果写成真实焊接质量验证；
- 不生成或替代 WPS/PQR；
- 不把项目推进变成 UI、权限、数据库等完整业务平台建设；
- 不把资料查询扩成无边界调研。

## 8. 完成标准

下一阶段可以认为完成第一轮样板收束，需要满足：

1. `stiffened-panel-fillet` 有明确场景定义、字段边界和资料来源；
2. 资料底座能说明该场景为什么可以进入仿真样板；
3. 至少一组仿真输出 bundle 能通过 gate 并导入平台；
4. 导入结果能形成围绕该场景的技能资产样板；
5. 报告明确区分仿真、公开资料、软件验证、真实质量验证和 WPS/PQR 边界；
6. README、details 和相关计划文档都指向同一条主线。

这不是最终产品完成标准，而是项目从“能力点验证”进入“场景样板验证”的阶段标准。
