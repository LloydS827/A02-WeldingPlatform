# 仿真优先的船舶焊接技能数据与工艺知识底座 — 设计 Spec

日期：2026-06-01
版本：v0.1
适用项目：A02 焊接技能大师平台
阶段：技能迁移 MVP 第一轮完成后的路线调整

---

## 0. 结论先行

下一阶段不再以“真机采集 + 经验访谈”为主路径。新的主路径是：

```text
船舶制造典型焊接任务梳理
-> 公开工艺资料与公开数据集整理
-> 约束仿真任务、参数范围和质量标签占位
-> 生成 Synthetic SkillDataset v2
-> 提取/迁移 WeldSkillPackage
-> 输出来源可追溯的评测报告
```

这条路线的目标不是证明真实焊接质量已经达标，而是用成本可控、资源可支撑、可重复的仿真数据，持续验证“焊接技能如何被结构化、迁移和评测”。

本阶段明确排除熔池路线。熔池视频、熔池形态识别、焊中闭环控制不进入本阶段设计，也不作为典型任务选择依据。

---

## 1. 已确认关键决策

1. 第二阶段主线改为“仿真优先 + 公开数据/资料约束”，不再叫“真实数据与工程化 MVP”。
2. 首要交付物是公开焊接数据集与工艺资料底座，而不是先做真机采集模板。
3. 真机采集保留为后续标定/验证接口，不进入当前阶段主路径。
4. 专家访谈保留为人工审查与规则补充，不作为主要数据来源。
5. 典型任务必须从船舶制造焊接场景出发，先整体了解行业与相关机器人焊接路线，再按易到难选取。
6. 本阶段不把 IP 风险作为约束；但仍记录来源、链接和字段覆盖度，方便后续复查。
7. 设计通过后进入实施计划阶段。

## 2. 背景与边界

第一阶段已经完成两条证据链：

- 经验结构化 POC：合成轨迹与扰动输入可以拆解为结构化工艺参数，并重组为可执行轨迹。
- 技能迁移 MVP：仿真样本可以进入 `SkillDataset`，生成 `WeldSkillPackage`，并完成条件迁移和报告输出。

现有 `details.md` 与 README 的下一阶段仍偏向“真机数据最小闭环”和“专家知识采集模板”。本 spec 要修正这个路线：真机和专家不取消，但降级为后续校准与审查；当前阶段先把仿真数据做实，把仿真的参数来源、任务来源和公开证据讲清楚。

### 2.1 本阶段做什么

- 建立公开资料清单：船舶焊接机器人/工艺路线、公开数据集、公开工艺参数资料。
- 把公开资料映射为结构化字段：焊缝类型、接头、板厚、坡口、焊接位置、焊接方法、电流、电压、速度、送丝、摆动模板、质量标签。
- 选取 2-3 个船舶制造典型仿真任务，按易到难推进。
- 扩展仿真数据生成，使样本不再只来自单一 straight-flat 单道任务。
- 输出证据报告，说明每个任务和参数的来源类别。

### 2.2 本阶段不做什么

- 不做真机焊接采集闭环。
- 不做技能大师访谈主流程。
- 不做熔池图像、熔池控制或焊中闭环自适应。
- 不做生产级平台界面。
- 不承诺焊缝真实质量达标。

## 3. 船舶制造任务调研原则

典型任务选择必须从船舶制造场景出发，而不是从已有代码方便性出发。

初筛参考资料包括：

- Hyundai Welding 的 shipbuilding cobot solution 资料，作为船舶场景协作焊接自动化参考。
- HD Hyundai / Hyundai Heavy Industries 相关公开报道与资料，作为大型船厂机器人焊接应用方向参考。
- KOBELCO shipbuilding welding 资料，作为船舶行业焊材、焊接工艺和自动化场景参考。
- 既有项目文档 `docs/project/船舶焊接工艺大脑平台整体规划方案.html` 中关于坡口、角焊缝、层道、轨迹和质量对象的定义。

资料使用方式：

- 只提炼任务族、焊缝对象、自动化痛点和工艺字段。
- 不把外部厂商方案当成可直接复用的数据资产。
- 不把厂商机器人能力写成当前项目已具备能力。

## 4. 典型任务路线

本阶段不直接锁定“Task A/B/C”。典型任务必须先经过船舶制造焊接任务调研，再进入场景确认。上一版中的平直角焊、双层底/双壳、板拼对接只能作为候选方向，不能直接作为已确认任务。

### 4.1 调研依据

初步调研显示，船舶焊接自动化不是单一“直线焊缝”问题，而是按制造阶段、构件对象、焊接位置和可达空间分化：

- HD Hyundai Mipo 的公开案例强调 subassembly welding、机器人/人工并行输送线、block welding tight compartments、焊接轨迹/可达性/碰撞/节拍仿真。
- KOBELCO shipbuilding 资料按 stage 梳理了 horizontal fillet、vertical upward、inner double-hull fillet、bottom shell / tank top / side shell butt 等船舶焊接对象。
- KRANENDONK panel welding gantry 资料强调 large stiffened panels、CAD seam detection、torch angles、travel speeds、stitch patterns 和 collision-free robot programs。
- 既有项目总规也把焊缝对象拆成接头形式、坡口类型、焊接位置、层道策略、轨迹对象和质量对象。

因此，本阶段先形成“船舶焊接任务族表”，再从中选 2-3 个仿真场景。不能仅凭代码已有 straight-flat 能力倒推任务选择。

### 4.2 船舶焊接任务族拆分

任务族表至少覆盖以下维度：

| 任务族 | 船舶制造环节 | 典型焊缝对象 | 接头/位置 | 仿真建模难度 | 当前处置 |
| --- | --- | --- | --- | --- | --- |
| 平面板拼接 | 钢板预处理、平面分段、panel line | bottom shell、tank top、deck、side shell 的板-板拼接 | butt，flat / horizontal | 中 | 候选，需区分 SAW/FCW/GMAW 工艺边界 |
| 加筋板/纵骨角焊 | 小组立、panel stiffener mounting、robot panel welding | stiffener-to-plate、longitudinal-to-panel、web-to-panel | fillet / tee，flat / horizontal | 低 | 优先候选，但需补焊脚、断续/连续焊、torch angle 字段 |
| 微型面板/腹板/隔板焊接 | micro panel、web、bulkhead subassembly | web、bulkhead、bracket、small stiffened structures | fillet / lap / tee，多短焊缝 | 中 | 候选，需补多焊缝序列和节点过渡 |
| 双层底/双壳内部角焊 | double bottom、double hull、block cell | inner double-hull fillet、double-bottom inside fillet | fillet，horizontal / vertical-up | 中高 | 候选，需补狭小空间、姿态切换、可达性占位 |
| 立向/仰位船体焊缝 | block assembly、erection stage | side shell vertical butt、overhead butt、vertical-up fillet | butt / fillet，vertical / overhead | 高 | 暂缓为探针，不作为第一批仿真主任务 |
| 厚板坡口多层多道 | 分段装配、总组/搭载 | V/X/K 坡口、厚板对接、长焊缝 | butt groove，多层多道 | 高 | 后续路线图，第一批只做简化字段占位 |
| 曲面与空间复杂焊缝 | 曲面外板、复杂节点 | curved seams、cross nodes、bracket intersections | 多接头、多姿态 | 很高 | 暂缓，不进入当前阶段 |

### 4.3 第一批场景选择规则

第一批仿真场景必须通过以下选择规则：

1. 必须能明确对应船舶制造环节，例如 panel line、小组立、subassembly、double bottom/double hull、block assembly。
2. 必须有至少 2 个公开来源支持该任务族存在，来源可以是船厂案例、焊材/设备厂商资料、标准/论文或既有项目总规。
3. 必须能转成 `SimulationScenarioSpec` 字段，不要求马上有完整机器人程序。
4. 必须明确哪些字段来自公开约束，哪些字段是仿真假设，哪些字段后续需要真机标定。
5. 必须不依赖熔池图像、熔池形态或焊中闭环数据。

### 4.4 建议的初始候选顺序

只有在完成 4.2 的任务族表和 4.3 的选择规则后，才允许确认第一批任务。当前推荐的候选顺序是：

| 优先级 | 候选方向 | 原因 | 进入仿真的前置条件 |
| --- | --- | --- | --- |
| P1 | 加筋板/纵骨角焊 | 船舶制造特征强，几何可控，机器人面板焊接资料较多 | 补齐焊脚、构件高度、连续/断续焊、torch angle、travel speed 字段 |
| P2 | 平面板拼接 / 简化对接焊 | 船体板材高频对象，可连接现有 straight-flat 能力 | 区分板拼 butt 与普通 straight-flat，补坡口/边界和工艺方法字段 |
| P3 | 微型面板/腹板/隔板多短焊缝 | 更贴近 subassembly，能验证多焊缝序列 | 补 weld seam list、节点过渡、焊缝顺序和可达性占位 |
| P4 | 双层底/双壳内部角焊 | 船舶场景强，现代/相关资料常提 confined space/block welding | 先完成 P1/P3，再引入姿态切换、狭小空间和多段可达性占位 |

最终第一批可以从 P1/P2/P3 中选 2-3 个；P4 更适合做第二轮增强或探针。

### 4.5 暂缓任务

以下任务暂缓：

- 高复杂多层多道全自动规划。
- 曲面船体空间焊缝。
- AMR 跨工位长焊缝自动分段。
- 熔池视觉闭环。
- 声纹/熔池/缺陷反向归因。

## 5. 数据与知识底座设计

新增一个资料底座层，先以文档/JSON/CSV 形式沉淀，不急于做数据库。

### 5.1 `PublicWeldKnowledgeBase`

保存公开资料与公开数据集的目录。

字段建议：

| 字段 | 说明 |
| --- | --- |
| `source_id` | 来源编号 |
| `source_type` | dataset / process_guide / vendor_case / standard / paper |
| `title` | 来源标题 |
| `url` | 来源链接 |
| `publisher` | 发布方 |
| `shipbuilding_relevance` | 与船舶制造任务的关系 |
| `covered_fields` | 覆盖哪些工艺字段 |
| `missing_fields` | 缺少哪些关键字段 |
| `usable_for` | scenario_selection / parameter_range / quality_label / benchmark |
| `notes` | 使用边界 |

用户已明确 IP 风险不用考虑，因此本阶段不需要做许可准入判断。但建议保留 `license_or_terms_note` 字段作为追溯信息，不作为阻塞项。

### 5.2 `SimulationScenarioSpec`

把资料底座转成仿真任务定义。

字段建议：

| 字段 | 说明 |
| --- | --- |
| `scenario_id` | 仿真场景编号 |
| `shipbuilding_task` | 船舶制造任务名 |
| `shipbuilding_context` | 对应船舶制造环节，例如小组立、双层底/双壳结构、分段板拼 |
| `difficulty` | easy / medium / hard |
| `weld_condition` | 可进入 `SkillSample` 的焊缝条件 |
| `parameter_ranges` | 电流、电压、速度、送丝、摆幅、摆频范围 |
| `motion_templates` | 可用摆动模板 |
| `quality_placeholders` | 质量标签占位 |
| `source_refs` | 参数和任务来自哪些公开资料 |
| `assumptions` | 仿真假设 |
| `evidence_role` | 区分 public_constraint / simulation_output / assumption / requires_real_validation_later |

### 5.3 `SyntheticSkillDataset v2`

在现有 `SkillDataset` 上扩展，不另造一套格式。

新增样本要明确：

- `source_type = simulation`。
- `license_and_rights` 可写内部生成数据。
- `recording_artifact` 可指向生成配置、图或报告。
- `quality_observation` 标注为仿真评分或公开资料标签占位，不能写成真实焊接结果。

## 6. 数据流

推荐数据流：

```text
公开资料初筛
-> PublicWeldKnowledgeBase
-> SimulationScenarioSpec
-> simlite / datagen 生成多任务样本
-> SkillDataset
-> WeldSkillPackage
-> TransferExperiment
-> EvidenceReport v2
```

报告必须展示四类来源：

- `simulated`：由仿真生成。
- `public_dataset`：来自公开数据集。
- `public_process_reference`：来自公开工艺资料。
- `assumption`：项目团队当前假设。

这样可以避免把仿真样本包装成真实数据，也能让后续真机标定知道该校准哪些字段。

用途：

- 识别船舶制造中的高频焊接任务。

### 7.2 公开数据集

候选来源：

- GDXray weld X-ray 数据集：适合缺陷/无损检测标签参考，不提供完整轨迹过程数据。  
  https://github.com/computervision-xray-testing/GDXray
- Zenodo Metal Arc Welding dataset：适合公开焊接过程/检测数据初筛。  
  https://zenodo.org/records/10017718

用途：

- 建立质量标签词表。
- 建立参数范围参考。
- 建立字段缺口表，明确哪些数据只能靠仿真生成。

### 7.3 工艺参数资料

候选来源：

- AWS 标准焊接工艺规程相关公开说明。  
  https://www.aws.org/about/get-involved/committees/b2-committee-on-procedure-and-performance-qualification/swps/
- Lincoln Electric、Miller、ESAB 等公开焊接参数指南或计算器。

用途：

- 提供电流、电压、焊速、送丝速度、材料厚度等范围约束。
- 标注参数来源是“公开工艺参考”，不是项目真实 WPS。

## 8. 组件设计

### 8.1 资料目录组件

职责：

- 维护公开来源清单。
- 标注字段覆盖度。
- 生成可读的资料审查表。

边界：

- 不下载大规模数据。
- 不做自动爬虫。
- 不判断 IP 准入。

### 8.2 场景规格组件

职责：

- 将任务族转成 `SimulationScenarioSpec`。
- 生成 2-3 个经公开资料支撑的船舶候选场景草案。
- 为每个任务绑定来源和假设。

边界：

- 不做复杂 CAD/船体三维建模。
- 不做真实机器人可达性求解。

### 8.3 仿真生成组件

职责：

- 复用现有 `datagen.synth` 和 `simlite`。
- 支持 fillet、butt、简化坡口、位置标签和多任务样本生成。
- 输出 `SkillDataset`。

边界：

- 仍是轻量运动学 + 工艺参数曲线仿真。
- 不做高保真熔池物理。

### 8.4 报告组件

职责：

- 输出 EvidenceReport v2。
- 展示任务、参数、来源、假设、迁移指标和风险。
- 明确哪些结果来自仿真，哪些来自公开资料。

边界：

- 不输出“真实焊接质量通过”的结论。

## 9. 错误处理与风险控制

| 风险 | 处理 |
| --- | --- |
| 公开资料与船舶任务不匹配 | 标注为通用焊接参考，不作为船舶任务依据 |
| 公开数据集缺少轨迹或电参 | 只用其质量标签/图像/缺陷字段，轨迹由仿真生成 |
| 参数范围冲突 | 保留多个来源，仿真场景使用保守范围并记录假设 |
| 船舶任务过复杂 | 先完成任务族表和选择规则，再从低复杂度候选中选择；复杂场景只进入路线图 |
| 仿真被误读为真机结论 | 报告与 `details.md` 均明确“仿真机制验证，不等于真实质量验证” |
| 熔池路线重新膨胀 | 本阶段交付物、典型任务、仿真字段、质量标签和报告证据均不得依赖熔池图像、熔池形态、熔池控制或焊中闭环数据；如提及熔池，仅限在“明确排除/未来不纳入本阶段”说明中出现 |

## 12. 当前设计自审

对照用户修正：

- 是否从船舶制造典型任务出发：是，第四部分已改为先建立船舶焊接任务族表，再选择具体场景。
- 是否参考现代/相关机器人公司路线：是，已把 Hyundai Welding、HD Hyundai/HHI、KOBELCO、Siemens HD Hyundai Mipo 案例、KRANENDONK 等列入任务调研来源。
- 是否避免主观锁定任务：是，平直角焊、双层底/双壳、板拼对接等只作为候选方向，需通过来源与字段覆盖闸门后确认。
- 是否从易到难：是，按建模难度、船舶制造环节和字段完整度排序，而不是直接固定 Task A/B/C。
- 是否排除熔池：是，本阶段明确不做熔池图像、熔池识别和闭环控制。
- 是否保留真机与专家但不依赖：是，真机/专家只作为后续校准、验证和审查。
- 是否避免把仿真夸大为真实焊接质量：是，报告和台账都要明确边界。
