## 0. 这份 Spec 在定义什么

本 Spec 不定义"平台"本身，而定义这一阶段（0→1，想法阶段）真正要交付的**两个产物**：

1. **一份风险驱动论证白皮书**（文档）——把 260522《船舶焊接工艺大脑平台整体规划方案》去风险化，产出可立项、可对内技术评审、可对上/对外汇报的方案与路线图。
2. **一个嵌入式关键预研 POC**（可生长的代码种子）——验证整个项目最核心、最不确定的能力：**大师焊接经验的结构化与可复现性（L1 为主，L2 探针）**。POC 的产出回填白皮书的风险判定，同时作为未来"结构化引擎"的雏形。

白皮书是"论证为纲"，POC 是"关键预研"，预研服务于论证。

> **北极星原则（执行期贯穿）**：一切产出必须**紧扣"焊接技能大师"这一主题与核心难点**——即"大师的焊接动作与参数如何被结构化、如何被机器人复现"。无论白皮书章节还是 POC 代码，凡偏离该命门、滑向"通用智能制造大平台"叙事的内容，一律收窄或移出。每个章节、每个模块都应能回答："它如何服务于大师技能的结构化与复现？"

### 0.1 阶段与能力的双轴定位

本阶段成果在公司既有研发流程中的坐标：

- **成熟度轴（四阶段）**：本白皮书 = 走完「想法」阶段的证据包 + 启动「MVP」阶段的先行证据（即嵌入式 POC）。
- **技术能力轴（L0–L3）**：当前技术目标瞄准 **L1（经验结构化）**，并对 **L2（经验泛化）** 做可行性探针。

两轴正交，构成第 4 部分路线图的二维表。

### 1.1 项目技术三分法（来自用户的总体划分）

整个项目技术上分三部分，本 Spec 沿用此划分组织风险表与路线图：

- **Part 1 — 数据采集与视觉**：坡口/焊道扫描、点云处理、多源同步采集、回放标注。参考甚至复用开源 rerun.io。
- **Part 2 — 经验结构化与机器人移植** ★最核心、难度最大★：大师焊接动作与参数 → 结构化工艺数据结构 → 机器人可执行。**关键预研锁定于此。**
- **Part 3 — 质量与熔池等后道**：焊后三维重建、焊前焊后对比、熔池/声纹、质量反向归因。

### 1.2 能力台阶定义（L0–L3，贯穿全文）

| 台阶 | 内容 | 可行性判断 |
|---|---|---|
| L0 录制-回放 | 同一工件复刻 TCP + 参数 | 易，价值低，不抗工件变化 |
| **L1 参数化/模板化** | 手法拆为 摆动模板 + 工作角/行进角/干伸/摆幅摆频/停留/层道 | **可做，近期真正护城河**（本质是焊接领域数据建模） |
| L2 条件化映射 | 坡口几何 → 自动出参数 + 摆动 + 层道，泛化到新坡口 | 价值与难度都在此，需数据 + 模型 |
| L3 闭环自适应 | 焊中看熔池/电弧实时调手法（大师"反射"） | 研究级难题，本阶段列入"暂不承诺" |

**核心张力（必须在白皮书中明示）**：大师真正"贵"的部分恰是 L3 的闭环自适应；开环复刻大师"平均手法" ≠ 大师技能。因此"经验结构化(L1)"与"经验泛化/自适应(L2/L3)"必须分开对待、分别承诺。

### 2.1 风险登记表字段规范

每一行是一条可质疑、可追溯的记录：

| 字段 | 含义 |
|---|---|
| 承诺原文 | 引自 260522 方案的原始表述（带章节号） |
| 拆解 | 把这条承诺翻译成可判定的技术命题 |
| 标签（诊断） | ✅ 已可做 / 🔧 工程可做需投入 / 🔬 需预研验证 / ⛔ 暂不承诺 |
| 处置（处方） | 继续 / 收窄 / 调整 / 合并 / 冻结 / 终止 |
| 依据 | 为什么这么判（成熟度、文献、本预研结论、资源约束等） |

诊断（标签）与处方（处置）互补：标签回答"能不能做"，处置回答"那要怎么办"。

## 3. 产物二：POC 架构（"经验结构化引擎"种子）

**核心判断：真正的护城河资产是 `model/` —— 焊接工艺数据结构本身。** 算法（decompose/recompose）会迭代，但数据结构是项目长期地基。

### 3.1 模块结构

```
weld-experience-engine/                 ← 可生长的代码种子（Python）
│
├─ model/        ★项目核心资产★  焊接工艺数据结构（纯定义，无业务逻辑）
│   ├─ WeldProcess       一条焊缝的完整工艺表达（工艺包数据内核）
│   ├─ WeaveTemplate     摆动模板(月牙/锯齿/8字/梯形)+ 可调参数
│   ├─ TrajectorySample  单点：t, X/Y/Z, Rx/Ry/Rz,(电参/力控可选)
│   ├─ LayerPass         层道结构：层序/道序/搭接/填充面积
│   └─ GrooveGeometry    坡口几何：角度/间隙/钝边/深度/断面面积
│
├─ datagen/      合成"理想大师轨迹" + 注入真实扰动
│   ├─ synth       摆动模板 + 工艺参数 → 理想轨迹（正向）
│   └─ perturb     叠加手抖/无效停顿/路径漂移（模拟人工示教）
│
├─ decompose/    ★L1 引擎★  轨迹 → 结构化工艺参数（逆向）
│   ├─ centerline  提取焊接中心线（剥离摆动）
│   ├─ weave       识别摆动模板类型 + 摆幅/摆频/左右停留
│   └─ posture     解算工作角/行进角/干伸/行进速度
│
├─ recompose/    结构化参数 → 机器人可执行轨迹（NURBS/直线/圆弧插补）
│
├─ metrics/      ★诚实度来源★  特征保留度量
│   ├─ 复现误差    recompose(decompose(traj)) vs 原轨迹（TCP/姿态误差）
│   ├─ 特征保真    工艺停留是否保住、抖动是否去掉
│   └─ L2 探针     新坡口 → 重组的定性评估
│
├─ viz/          rerun 可视化（顺带实测 rerun 当采集底座是否够格）
│
└─ report/       跑出数字 + 图 → 回填白皮书第2部分🔬判定
```

### 3.2 数据流（闭环自证）

```
摆动模板+参数 ──synth──▶ 理想轨迹 ──perturb──▶ "拟真大师轨迹"
                                                      │
                                                  decompose (L1)
                                                      ▼
                                  结构化工艺参数 ◀── 与原始参数对比 = 拆解准确度
                                                      │
                                                  recompose
                                                      ▼
                                  可执行轨迹 ──metrics──▶ 复现误差 / 特征保真
                                                      │
                                                viz(rerun) + report
```

因为是"合成→拆解→重组"，**原始参数已知（ground truth）**，所以拆解准不准、特征丢没丢都可量化——这是白皮书第 5 部分的硬证据，并顺带回答"rerun 当底座够不够格"。

### 3.3 诚实度设计（关键）

metrics 专门测**抗扰动**：扰动从小到大施加，找出 decompose 开始失效的"失效边界"。白皮书如实写出该边界，而非只报最好结果。这正是"敢说做不到"的可信度来源。

### 3.4 技术栈

| 项 | 选择 | 备注 |
|---|---|---|
| 语言 | Python | numpy/scipy 做轨迹数学；rerun 有 Python SDK；迭代快 |
| 数据结构 | dataclass / pydantic | 干净可序列化，未来可直接 dump 成工艺包 JSON |
| 插补 | scipy 样条 / geomdl(NURBS) | **逐个判**是否引库，先验证再决定（D4） |
| 可视化 | rerun | 作为 viz 唯一依赖引入，实测其作"经验采集驾驶舱"底座的体验，结论写入第3部分 |
| 测试 | pytest | 见 3.5 |

### 3.5 测试策略

- 每个单元独立测，职责单一、接口清晰。
- **核心：往返测试（round-trip）**——`decompose ∘ recompose` 对理想轨迹应近乎无损（合成数据提供 ground truth）；对扰动轨迹量化误差。天然 TDD 友好。
- 抗扰动测试：参数化扫描扰动幅度，记录误差曲线与失效边界。

## 4. 范围边界（YAGNI）

**本阶段做：**
- 白皮书 6 部分全文（第 0 部分最后写）。
- POC：Part 2 的 L1 结构化引擎 + L2 探针，合成+扰动数据，往返与抗扰动度量，rerun 可视化。

**本阶段不做：**
- 不做真机采集 / 不接真实机器人（无真机，D1）。
- 不做 L3 焊中闭环自适应（列入⛔，D5/1.2）。
- 不做 Part 1 完整采集底座工程化、不做 Part 3 质量归因模型（路线图里规划，不在本期 POC）。
- 不展开公司战略框架（D10）。
- 不重复建设 ERP/MES/PLM/QMS（沿用 260522 系统边界）。
