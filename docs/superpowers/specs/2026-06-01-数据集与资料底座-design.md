# 数据集与资料底座 Design Spec

日期：2026-06-01  
版本：v0.1  
适用项目：A02 焊接技能大师平台  
阶段：仿真优先知识闸门通过后的资料底座建设

---

## 0. 结论先行

本阶段采用 **A+：Manifest-first 资料底座**。

本轮不把大体量公开数据下载进 git 仓库，也不直接进入批量 `SyntheticSkillDataset v2` 生成。先建立一个可审查、可追溯、可执行 gate 的资料底座：

```text
公开资料/公开数据集/项目资料
-> SourceCard / DatasetCard
-> FieldCoverageMatrix
-> TaskEvidenceMap
-> DataFoundationGate
-> 后续 SyntheticSkillDataset v2 生成计划
```

该底座的作用是回答三件事：

1. 哪些来源可以支撑船舶焊接任务选择。
2. 哪些字段有公开资料约束，哪些字段仍是仿真假设。
3. 哪些候选场景已经具备进入 `SyntheticSkillDataset v2` 的证据条件。

本阶段仍然明确排除熔池图像、熔池控制和焊中闭环路线。任何公开资料或数据集即使包含相关内容，也只能登记为“本阶段不使用/未来路线”，不得进入当前 JSON 输出、字段依赖或仿真输入。

---

## 1. 已确认关键决策

1. 本轮采用 Manifest-first，不下载大文件，只保留小样本接口。
2. 资料底座文档放在 `docs/data-foundation/`。
3. 可执行 gate 和报告能力继续放在 `weld-experience-engine/weldcore/knowledge` 与 `weldcore.report`。
4. 第一版验收目标：
   - 总来源不少于 20 条。
   - 公开来源不少于 15 条。
   - 船舶制造强相关来源不少于 8 条。
   - 公开数据集不少于 6 条。
5. 本轮产物包含 Markdown spec 与 HTML 阅读版。
6. 后续任务主线是：

```text
资料底座通过 gate
-> SyntheticSkillDataset v2 生成计划
-> 仿真样本与报告实现
```

---

## 2. 背景与当前缺口

上一阶段已经完成了第一道知识闸门：

- `PublicWeldKnowledgeBase`：9 条 seed 来源，其中 8 条公开来源。
- `ShipbuildingTaskFamily` gate：用来源、字段覆盖和 `assumption_fields` 验证任务族。
- `SimulationScenarioSpec`：生成 3 个候选船舶焊接仿真场景。
- `scenario_report`：输出 sources、task families、scenarios、field coverage 和 evidence。

但这些能力仍然偏“seed 级别”。下一阶段要把它升级成正式底座：

- 来源不应只写在 Python seed 里，还需要可被非研发人员阅读和审查的资料卡。
- 公开数据集需要记录体量、模态、schema、下载策略和使用边界。
- 船舶任务族需要看到“哪些来源支持哪些任务字段”的映射矩阵。
- 后续 `SyntheticSkillDataset v2` 的计划必须从这个底座派生，而不是凭经验直接生成样本。

---

## 3. 范围边界

### 3.1 本阶段做什么

- 建立 `docs/data-foundation/` 下的资料底座文档与机器可读 manifest。
- 扩展当前 seed 来源池到不少于 20 条。
- 把来源分为 `SourceCard`、`DatasetCard`、`TaskEvidenceMap`、`FieldCoverageMatrix`。
- 新增或扩展可执行 gate，验证来源数量、字段完整性、任务证据覆盖和禁止字段。
- 生成 `data_foundation_report`，输出资料底座证据、覆盖矩阵和下一步任务建议。
- 根据资料底座结果，形成后续 `SyntheticSkillDataset v2` 的实施计划。

### 3.2 本阶段不做什么

- 不下载大体量公开数据集进 git。
- 不生成批量 `SyntheticSkillDataset v2`。
- 不实现真机采集、机器人程序或生产控制接口。
- 不把公开资料或仿真标签写成真实焊接质量验证。
- 不纳入熔池图像、熔池控制或焊中闭环字段。

## 4. 资料底座目录设计

新增目录：

```text
docs/data-foundation/
├── README.md
├── source-cards/
│   ├── shipbuilding-automation.md
│   ├── process-guides.md
│   ├── public-datasets.md
│   └── standards-and-defect-vocabulary.md
├── manifests/
│   ├── sources.json
│   ├── datasets.json
│   ├── field_coverage.csv
│   └── task_evidence_map.json
└── reports/
    └── data_foundation_evidence.md
```

设计原则：

- Markdown 给业务、工艺和项目人员阅读。
- JSON/CSV 给测试、报告和后续数据生成计划使用。
- 不把外部大文件放入仓库；只记录 URL、大小、schema、下载策略和使用边界。
- 资料卡必须与 `weldcore.knowledge` 的可执行对象可以互相映射。

## 5. 数据模型

### 5.1 `SourceCard`

`SourceCard` 描述任何可用于任务选择、工艺约束、字段覆盖或标签词汇的来源。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `source_id` | 稳定来源编号 |
| `source_type` | `vendor_case` / `process_guide` / `dataset` / `standard` / `paper` / `project_internal` |
| `title` | 来源标题 |
| `url` | 公开 URL 或项目内相对路径 |
| `publisher` | 发布方 |
| `public_access` | `public` / `project_internal` / `requires_screening` |
| `shipbuilding_relevance` | 与船舶制造任务的关系 |
| `covered_fields` | 可支撑字段 |
| `missing_fields` | 明确缺失字段 |
| `usable_for` | `scenario_selection` / `parameter_range` / `quality_label` / `benchmark` / `schema_reference` |
| `source_refs` | 对应 spec、资料页、章节或备注 |
| `assumptions` | 使用该来源时引入的假设 |
| `use_boundary` | 使用边界，必须明确“可用于什么”和“不能用于什么” |
| `notes` | 补充备注，不替代 `use_boundary` |

### 5.2 `DatasetCard`

`DatasetCard` 是 `SourceCard` 的数据集扩展，用于公开焊接数据集和后续小样本缓存。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `dataset_id` | 数据集编号 |
| `source_id` | 对应 `SourceCard` |
| `modalities` | `xray_image` / `surface_image` / `current_voltage_timeseries` / `robot_pose` / `scan_3d` / `video` / `metadata` |
| `size_note` | 体量说明 |
| `download_policy` | `manifest_only` / `sample_cache_later` / `external_cache_only` |
| `schema_summary` | 字段或文件结构摘要 |
| `quality_label_type` | 缺陷标签、视觉标签、过程标签或无标签 |
| `shipbuilding_fit` | `direct` / `adjacent` / `generic` / `benchmark_only` |
| `use_boundary` | 只能如何使用，不能如何使用 |

### 5.3 `FieldCoverageMatrix`

字段覆盖矩阵用于回答“每个字段由哪些来源支撑”。

第一版字段分组：

- 任务上下文：`shipbuilding_context`、`manufacturing_stage`、`weld_object`
- 接头与位置：`joint_type`、`weld_position`、`groove_geometry`
- 工艺参数：`current`、`voltage`、`wire_feed`、`travel_speed`
- 运动字段：`trajectory`、`robot_pose`、`torch_angle`、`motion_template`
- 质量与标签：`defect_label`、`quality_label`、`inspection_reference`
- 仿真边界：`assumption_field`、`requires_real_validation_later`

### 5.4 `TaskEvidenceMap`

`TaskEvidenceMap` 把任务族与来源连接起来。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `family_id` | 船舶焊接任务族 |
| `required_sources` | 至少需要哪些来源类别 |
| `supporting_source_ids` | 实际来源 |
| `covered_required_fields` | 已覆盖字段 |
| `assumption_fields` | 仍为仿真假设的字段 |
| `readiness` | `ready_for_synthetic_v2_plan` / `needs_more_sources` / `defer` |
| `next_action` | 下一步任务建议 |

## 7. Gate 设计

### 7.1 Source gate

必须验证：

- 总来源数不少于 20。
- 公开来源不少于 15。
- 船舶制造强相关来源不少于 8。
- 每条来源必须有 `usable_for`、`covered_fields`、`missing_fields`、`source_refs`、`assumptions`、`notes`。
- 每条来源必须声明 `public_access` 与 `use_boundary`；`notes` 只能作为补充备注，不能替代 `use_boundary`。
- 禁止字段不得出现在 JSON 输出或当前阶段字段依赖中。

### 7.2 Dataset gate

必须验证：

- 公开数据集不少于 6。
- 每个数据集都有 `modalities`、`size_note`、`download_policy`、`schema_summary`。
- `download_policy` 默认不能是“下载进 git”。
- 大体量数据集只能登记为 `manifest_only` 或 `external_cache_only`。
- 如果未来加入小样本缓存，必须单独记录 checksum、来源 URL、裁剪规则和不可替代性。

### 7.3 Field coverage gate

必须验证：

- 每个候选任务族的 required fields 要么有来源覆盖，要么列入 `assumption_fields`。
- 至少 3 个任务族达到 `ready_for_synthetic_v2_plan`，这是第一版硬 gate，不是后续建议项。
- 任务族不能只由通用焊接数据集支撑，必须至少有一个船舶制造上下文来源。
- `quality_label` 只能标注为公开标签词汇或仿真占位，不得写成真实质量结果。

### 7.4 Report gate

`data_foundation_report` 必须：

- 输出来源数量、公开来源数量、数据集数量和船舶强相关数量。
- 当船舶强相关来源少于 8 条时失败，而不是只在报告中提示。
- 输出字段覆盖矩阵。
- 输出任务证据映射。
- 输出下一步 `SyntheticSkillDataset v2` 计划建议。
- 当 source/dataset/field/task gate 失败时抛出明确错误。

## 9. 后续任务规划输出

本阶段完成后，必须形成下一阶段计划输入：

1. 可进入 `SyntheticSkillDataset v2` 的任务族列表。
2. 每个任务族的字段来源与假设字段。
3. 每个任务族建议生成的样本类型，例如直线、断续、短焊缝序列、姿态切换占位。
4. 哪些字段需要仿真生成，哪些字段只来自公开约束。
5. 哪些字段后续需要真机标定。

计划输出不是“立即生成数据”，而是给下一轮实施计划提供可审查依据。

## 10. 验收标准

完成本阶段 design/implementation 后，应满足：

- `docs/data-foundation/` 有可读资料底座文档。
- manifest 中总来源不少于 20。
- 公开来源不少于 15。
- 船舶制造强相关来源不少于 8。
- 公开数据集不少于 6。
- 每个来源和数据集都有完整字段与使用边界。
- 至少 3 个任务族达到 `ready_for_synthetic_v2_plan`。
- 报告清楚说明哪些是公开约束、哪些是仿真假设、哪些需要真机验证。
- JSON/CSV 输出不含熔池、焊池或焊中闭环依赖字段。
- README 和 `details.md` 说明本阶段完成的是资料底座，不是 `SyntheticSkillDataset v2`。
- 现有命令继续通过：

```bash
python -m pytest -q
python -m weldcore.report.generate
python -m weldcore.report.mvp_report
python -m weldcore.report.scenario_report
```

如果 `uv` 已安装，必须优先使用：

```bash
uv run pytest -q
uv run python -m weldcore.report.generate
uv run python -m weldcore.report.mvp_report
uv run python -m weldcore.report.scenario_report
```

## 11. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 公开数据集体量过大 | 只做 manifest，默认不下载进 git |
| 来源很多但字段不可用 | `covered_fields` / `missing_fields` / `usable_for` gate |
| 通用焊接数据冒充船舶场景 | `shipbuilding_relevance` 与任务族至少一个船舶来源 gate |
| 把仿真标签写成真实质量 | `quality_label` 必须区分 public vocabulary / simulation placeholder / real validation later |
| 熔池路线混入当前阶段 | source/dataset/task/scenario/report 全链路禁止字段扫描 |
| 文档与代码底座分裂 | manifest 是单一事实源，Markdown 由 manifest 摘要或同步检查 |

## 12. 推荐执行顺序

1. 建立资料底座数据模型与 manifest schema。
2. 迁移现有 9 条 seed 来源到 manifest。
3. 扩展到不少于 20 条来源和不少于 6 个公开数据集。
4. 生成字段覆盖矩阵和任务证据映射。
5. 实现 `data_foundation_report`。
6. 更新 README 与 `details.md`。
7. 基于通过 gate 的任务族，撰写 `SyntheticSkillDataset v2` 实施计划。
