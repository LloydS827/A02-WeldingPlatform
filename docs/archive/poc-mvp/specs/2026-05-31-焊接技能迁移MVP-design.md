# 焊接技能迁移 MVP — 设计 Spec

日期：2026-05-31
版本：v0.1
阶段：从想法阶段进入 MVP 阶段前的头脑风暴定稿
适用项目：A02 焊接技能大师平台

---

## 0. 结论先行

上一阶段 POC 已证明一件事：在合成轨迹和人工扰动条件下，焊接轨迹可以被拆解为结构化工艺参数，并重组为可执行轨迹。

MVP 阶段要证明更核心的问题：

> 技能大师的焊接技能能否被结构化为技能包，并在相近但变化后的焊缝条件下迁移复现。

MVP 不以“平台页面完整”作为验收，而以“技能迁移实验成立”作为验收。推荐路线是：

```text
仿真优先生成技能样本
-> Rerun 多源数据采集/回放驾驶舱
-> 统一 Skill Dataset
-> 结构化为 Weld Skill Package
-> 在变化后的焊缝条件下迁移复现
-> 输出软件原型、数据证据、评测报告和 IP 线索
```

核心策略：

- **先仿真，后真机**：仿真路线最容易立即开始；真机数据接口先预留，条件成熟后接入。
- **专家知识同步补充**：专家经验用于定义模板、规则、字段和人工确认标准，不单独替代实验数据。
- **Rerun 做驾驶舱**：Rerun 负责多源时间轴记录、回放、标注和调试，不作为生产数据库或机器人控制系统。
- **核心资产自有**：`SkillDataset`、`WeldSkillPackage`、迁移评测协议和工艺语义模型必须自有。

## 1. 背景与边界

### 1.1 已完成基础

仓库当前已有 `weld-experience-engine` POC：

- `Trajectory`、`WeaveTemplate`、`GrooveGeometry`、`LayerPass`、`WeldProcess` 等基础数据结构。
- 合成轨迹、扰动注入、decompose、recompose、metrics、report。
- 月牙、锯齿、梯形、8 字形摆动模板。
- Rerun 可选可视化入口。
- POC 评测报告与白皮书证据。

上一阶段结论应保留：L1 经验结构化可以继续推进，但真机样本、多焊缝类型和真实工艺质量尚未被证明。

### 1.2 MVP 不解决什么

MVP 阶段不承诺：

- 高保真熔池物理仿真。
- 焊中熔池闭环自适应控制。
- 复杂多层多道的完整自动规划。
- 任意坡口/任意姿态的自动泛化。
- 生产级数据库、MES/PLM/QMS 集成。
- 真实机器人控制总线。

这些能力可以进入路线图，但不能成为 MVP 验收前提。

## 2. MVP 成功标准

MVP 成功标准是一条可复现实验：

```text
同一种典型焊接技能
在源焊缝条件 A 中形成技能包
在相近但变化后的焊缝条件 B 中重组执行
并能用轨迹、姿态、电参、焊缝条件、人工确认指标证明核心手法没有丢
```

建议首个任务：

| 项 | MVP 选择 |
| --- | --- |
| 焊缝任务 | 直线平焊、单道、简单坡口或无坡口 |
| 数据来源 | 仿真数据为主，专家知识补充，真机接口预留 |
| 核心对象 | `WeldSkillPackage` |
| 迁移变化 | 焊缝长度、坡口宽度、板厚、摆幅需求等小范围变化 |
| 验收指标 | 轨迹 RMS、姿态偏差、摆幅/摆频误差、电参曲线偏差、工艺人员确认 |
| 产物 | 可运行代码、Rerun 回放、数据样本、评测报告、IP 线索清单 |

验收重点不是“焊接质量最终最优”，而是“技能包迁移机制是否成立”。真实焊接质量需要真机、焊材、工艺评定和质量检测，进入后续阶段。

## 3. 核心数据模型

MVP 的数据模型分三层：原始样本、结构化技能包、迁移评测记录。

### 3.1 `SkillDataset`

`SkillDataset` 是所有数据源的统一入口，仿真、真机和专家知识都要转成这一层。

字段建议：

| 字段 | 说明 |
| --- | --- |
| `dataset_id` | 数据集编号 |
| `source_type` | `simulation` / `real_robot` / `expert_knowledge` / `hybrid` |
| `task` | 焊接任务定义 |
| `samples` | 多条 `SkillSample` |
| `schema_version` | 数据格式版本 |
| `license_and_rights` | 数据来源、授权、IP 归属说明 |

### 3.2 `SkillSample`

一条样本对应一次焊接动作或一次仿真 demonstration。

字段建议：

| 字段 | 说明 |
| --- | --- |
| `sample_id` | 样本编号 |
| `weld_condition` | 焊缝类型、坡口、材料、板厚、焊接位置等 |
| `trajectory` | TCP 位置、姿态、时间戳 |
| `process_signal` | 电流、电压、送丝、速度等时间序列 |
| `events` | 起弧、收弧、左右停留、人工标注、异常段 |
| `quality_observation` | 仿真评分、人工确认、焊后结果占位 |
| `recording_artifact` | 可选的记录文件或回放索引 |

### 3.3 `WeldSkillPackage`

`WeldSkillPackage` 是 MVP 的核心 IP 载体，表示可以迁移复现的结构化技能。

字段建议：

| 字段 | 说明 |
| --- | --- |
| `package_id` | 技能包编号 |
| `source_sample_ids` | 来源样本 |
| `applicable_conditions` | 适用焊缝条件范围 |
| `motion_skill` | 行进速度、摆动模板、摆幅、摆频、停留、轨迹策略 |
| `posture_skill` | 工作角、行进角、干伸、姿态约束 |
| `process_skill` | 电流、电压等参数曲线或阶段规则 |
| `transfer_rule` | 条件变化时如何缩放、重采样或重新参数化 |
| `human_review` | 专家/工艺人员确认记录 |
| `evaluation` | 复现和迁移评测摘要 |

### 3.4 `TransferExperiment`

迁移实验记录源条件 A 到目标条件 B 的全过程。

字段建议：

| 字段 | 说明 |
| --- | --- |
| `experiment_id` | 实验编号 |
| `source_condition` | 源焊缝条件 |
| `target_condition` | 目标焊缝条件 |
| `skill_package_id` | 使用的技能包 |
| `recomposed_trajectory` | 迁移后轨迹 |
| `metrics` | RMS、姿态误差、电参误差、模板保真 |
| `decision` | pass / review / fail |
| `notes` | 风险、异常、人工判断 |

## 4. 数据来源策略

### 4.0 三条路线比较

MVP 阶段有三条候选路线：

| 路线 | 做法 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| 仿真优先 | 先用轻量仿真生成任务、样本、条件变化和迁移评测 | 马上能开始，可重复，有 ground truth | 仿真不能直接证明真实焊接质量 | **推荐主线** |
| 真机优先 | 先建设机器人/焊机/传感器采集链路 | 证据最硬，贴近真实生产 | 成本高、周期长，容易被设备集成拖住 | 预留接口，后续接入 |
| 专家知识优先 | 先整理大师经验、模板、规则和确认标准 | 成本低，能快速形成工艺语义 | 缺少动作数据和迁移评测，容易变成静态知识库 | 作为仿真主线的补充 |

推荐采用“仿真优先 + 专家知识补充 + 真机接口预留”。这条路线符合“是否马上能开始”的标准，也能避免等待完美条件。

### 4.1 仿真数据

仿真是 MVP 的主数据源，因为它能马上开始、可控、可重复、可生成 ground truth。

MVP 不要求一开始就做高保真焊接物理。第一阶段可以使用“运动学 + 焊缝几何 + 工艺参数曲线”的轻量仿真任务环境，先验证技能迁移协议。

仿真平台分层选择：

| 层级 | 选择 | 用途 |
| --- | --- | --- |
| L0 立即开始 | 当前 `weldcore.datagen` 扩展为 `simlite` | 快速生成任务、条件变化和迁移样本 |
| L1 候选接入 | ManiSkill / SAPIEN 风格任务环境 | 借鉴 robotics task、demonstration、evaluation 范式 |
| L2 后续评估 | Isaac Sim / ROS/MoveIt / 厂商离线编程 | 机器人可达性、碰撞、控制器相关验证 |

ManiSkill 的启发是“任务环境 + demonstration 数据 + 评测基准”，不是直接提供焊接物理。MVP 应借鉴其组织方式，而不是等待它完整覆盖焊接。

参考链接：

- ManiSkill 官网：https://www.maniskill.ai/
- ManiSkill GitHub：https://github.com/haosulab/ManiSkill
- ManiSkill Docs：https://maniskill.readthedocs.io/

用户提供的微信公众号链接当前访问时触发微信环境验证，正文未能自动抓取。后续如果需要引用其中观点，应由人工摘录关键段落后再进入项目文档。

### 4.2 真机数据

真机数据价值最高，但不作为 MVP 第一个阻塞项。

MVP 先预留真机接口：

- TCP 位姿时间序列。
- 姿态和速度。
- 电流、电压、送丝等工艺参数。
- 焊缝/坡口几何。
- 起弧、收弧、停留、异常等事件标注。
- 可选视频、点云、力控信号。

真机数据进入后，必须经过同一套 `SkillDataset` 适配层，而不是绕过核心数据模型。

### 4.3 专家知识

专家知识不是“文字知识库”而已，应结构化进入技能包：

- 常见焊缝任务的模板选择。
- 摆幅、摆频、停留和速度的经验区间。
- 电流、电压的阶段性调整规则。
- 什么变化可以靠缩放迁移，什么变化必须重新试焊。
- 工艺人员确认标准。

专家知识用于补齐仿真不包含的工艺语义，并形成 IP 线索。

## 5. Rerun 模块定位

Rerun 在 MVP 中定位为：

> 多源数据采集与回放驾驶舱。

它负责让研发人员和工艺人员看到数据，而不是替代核心业务模型。

### 5.1 Rerun 做什么

- 轨迹、姿态、焊缝几何、电参曲线的统一时间轴回放。
- 对比原始样本、结构化结果、迁移复现结果。
- 记录仿真样本和未来真机样本。
- 支持人工标注事件，例如左右停留、异常停顿、起弧/收弧。
- 作为调试和演示入口。

### 5.2 Rerun 不做什么

- 不作为生产数据库。
- 不作为机器人控制总线。
- 不作为工艺包版本管理系统。
- 不作为长期训练数据格式本身。

### 5.3 MVP 中的 Rerun 交付

MVP 应形成一个 `rerun_bridge` 或等价模块：

```text
SkillDataset / SkillSample / TransferExperiment
-> Rerun logging adapter
-> .rrd 或 live viewer
-> 人工回放、对比、标注
```

Rerun 适配层只依赖公开数据结构，不把 Rerun SDK 类型泄漏到核心模型里。这样未来可替换可视化工具，也不会损害自有数据资产。

参考链接：

- Rerun 官网：https://www.rerun.io/
- Rerun Docs：https://www.rerun.io/docs

## 6. 开源生态复用原则

选择标准：

| 标准 | 问题 |
| --- | --- |
| 省事 | 是否能马上减少工作量 |
| 绑深 | 是否会把核心架构绑死 |
| 可控 | 是否可调试、可替换、可离线运行 |
| 运维 | 是否易安装、易部署、易长期维护 |
| 可替代 | 是否有备选方案 |
| IP 安全 | 是否影响自有成果、专利和软著边界 |

候选表：

| 模块 | 候选 | MVP 决策 |
| --- | --- | --- |
| 多源回放 | Rerun | 引入，作为驾驶舱和记录工具 |
| 轻量仿真 | 现有 `weldcore.datagen` 扩展 | 立即使用，保证能开工 |
| 机器人仿真范式 | ManiSkill / SAPIEN | 调研并设计 adapter，不阻塞第一版 |
| 高保真机器人仿真 | Isaac Sim | 后续评估，不作为 MVP 前置依赖 |
| 点云几何 | Open3D / PCL | 未来真机/视觉接入时优先复用 |
| 运动规划 | MoveIt / 厂商 SDK | 设备明确后再定 |
| 数学计算 | numpy / scipy | 继续使用 |
| 工艺包模型 | 自有 | 必须自有 |

开源复用底线：

> 工具能复用就复用，核心技能表达和迁移评测必须自有。

## 7. 技能迁移实验设计

### 7.1 实验流程

```text
定义源任务 A
-> 生成或导入源样本
-> decompose 得到 WeldSkillPackage
-> 定义目标任务 B
-> 根据 transfer_rule 重组轨迹和参数
-> 生成 TransferExperiment
-> Rerun 回放对比
-> metrics 判断 pass/review/fail
-> 人工确认并写入报告
```

### 7.2 首批迁移变量

先选小范围、可解释、容易验证的变量：

| 变量 | 例子 | 迁移方式 |
| --- | --- | --- |
| 焊缝长度 | 100 mm -> 150 mm | 中心线重采样，保持摆频/速度或按规则缩放 |
| 坡口宽度 | 轻微变宽 | 调整摆幅或边缘停留 |
| 板厚 | 小范围变化 | 调整电参区间和层道占位 |
| 目标速度 | 工艺要求变化 | 重采样时间轴并检查摆频保真 |

### 7.3 评测指标

| 指标 | 含义 |
| --- | --- |
| 轨迹 RMS | 迁移轨迹与目标参考轨迹的空间差异 |
| 姿态偏差 | 工作角、行进角、干伸的保真度 |
| 摆动保真 | 摆幅、摆频、模板、左右停留是否保留 |
| 电参曲线偏差 | 电流、电压阶段或曲线是否符合迁移规则 |
| 条件适配 | 目标焊缝条件是否落在技能包适用范围内 |
| 人工确认 | 工艺人员/专家判断是否保留核心手法 |

### 7.4 pass/review/fail

MVP 不应只输出数值，还应输出决策：

- `pass`：指标达标，人工确认通过。
- `review`：指标部分达标，需要工艺人员审查。
- `fail`：超出适用范围或关键指标失败。

这个机制比单纯“生成轨迹”更接近真实工艺流程。

## 8. MVP 软件架构

建议在现有 `weld-experience-engine` 上生长，不另起炉灶。

```text
weld-experience-engine/
├─ weldcore/
│  ├─ model/
│  │  ├─ trajectory.py
│  │  ├─ process.py
│  │  ├─ skill.py              # 新增：SkillDataset / SkillSample / WeldSkillPackage
│  │  └─ experiment.py         # 新增：TransferExperiment
│  ├─ datagen/
│  │  └─ ...                   # 继续保留现有合成和扰动
│  ├─ sim/
│  │  ├─ task.py               # 新增：焊接任务环境定义
│  │  ├─ simlite.py            # 新增：轻量仿真样本生成
│  │  └─ adapters/
│  │     └─ maniskill.py       # 新增：候选 adapter，占位/调研型
│  ├─ decompose/
│  ├─ recompose/
│  ├─ transfer/
│  │  ├─ rules.py              # 新增：迁移规则
│  │  └─ evaluate.py           # 新增：迁移评测
│  ├─ viz/
│  │  └─ rerun_bridge.py       # 新增或扩展：SkillDataset/Experiment -> Rerun
│  └─ report/
│     └─ mvp_report.py         # 新增：MVP 迁移实验报告
└─ tests/
   ├─ test_skill_model.py
   ├─ test_simlite.py
   ├─ test_transfer_rules.py
   ├─ test_transfer_evaluate.py
   └─ test_rerun_bridge.py
```

设计原则：

- 现有 POC 模块继续可运行。
- 新模型不破坏旧模型。
- `rerun_bridge` 是边界层，不污染 `model`。
- `maniskill.py` 第一阶段可以是 adapter 接口和调研占位，不把安装 ManiSkill 作为基础测试依赖。
- 所有迁移实验都能用 pytest 和报告命令复现。

## 9. IP、论文与成果规划

MVP 从一开始就应沉淀知识产权线索，而不是等软件做完再补。

### 9.1 软件/软著方向

- 焊接技能迁移实验平台。
- 焊接大师技能包结构化与复现系统。
- Rerun 驱动的多源焊接数据回放与标注模块。
- 焊接技能迁移评测与报告生成工具。

### 9.2 专利线索

候选专利方向：

1. 一种焊接大师经验的多源数据结构化与机器人复现方法。
2. 一种基于仿真样本和专家知识融合的焊接技能迁移方法。
3. 一种面向焊接工艺包的轨迹、姿态、电参、焊缝条件联合表达方法。
4. 一种基于多源时间轴回放的人在回路焊接技能包确认方法。
5. 一种面向焊缝条件变化的焊接摆动模板迁移与保真评测方法。

### 9.3 论文/技术报告方向

- 焊接技能结构化表达与迁移评测框架。
- 仿真驱动的焊接机器人技能数据集构建方法。
- 面向船舶焊接的技能包 schema 与可解释复现指标。
- 多源焊接过程数据回放与人在回路标注方法。

### 9.4 IP 边界提醒

- 开源工具可作为工程支撑，但论文/专利主张应落在自有数据结构、迁移规则、评测协议和人机协同确认流程。
- 对外文档要避免把开源工具包装成自有发明。
- `license_and_rights` 应进入数据集元数据，避免后续数据资产归属不清。

## 10. 风险与自审

### 10.1 主要风险

| 风险 | 处置 |
| --- | --- |
| 仿真过于简化，不能代表真实焊接 | 明确 MVP 只证明技能迁移机制，真机标定是后续阶段 |
| 过早绑定某个仿真平台 | 先做自有 schema 和 adapter，不让平台决定核心模型 |
| Rerun 被误用为数据库或控制总线 | 在架构中限制为可视化/记录边界层 |
| 专家知识停留在文字 | 必须结构化为模板、规则、确认标准 |
| IP 成果被开源依赖稀释 | 自有创新点放在工艺语义模型、迁移规则和评测协议 |
| MVP 又膨胀成大平台 | 验收只围绕一条典型焊缝任务和迁移实验 |

### 10.2 自审结果

对照本轮用户目标：
