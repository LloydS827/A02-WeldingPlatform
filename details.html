焊接技能大师平台项目进展说明

更新时间：2026-06-05

这份文件用于跟踪 A02「焊接技能大师平台」的实际进展、已有能力、待补能力和下一步计划。它面向项目负责人、业务人员、工艺人员和非技术读者，尽量用直白语言说明项目现在到底走到哪一步。

维护方式

这份文件需要随着项目推进及时更新。凡是项目阶段、已有能力、待补能力、下一步计划、风险判断或关键交付物发生变化，都应该同步修改本文件。

未来 Agent 在阶段或范围变化时必须检查本文件。更新时请保持面向非技术读者的表达方式，明确区分“已经完成”“正在验证”“后续需要补充”，不要把仿真或软件原型结果夸大为真实焊接质量结论。

本文件应同步维护 HTML 阅读版。后续如果更新根目录 README.md、本文件或类似面向读者的阶段/路线说明，也要同步创建或刷新对应的 .html 阅读副本，方便项目负责人、业务人员和工艺人员直接阅读。

一句话说明

本项目要把焊接技能大师的经验，从口头描述、纸面工艺卡或单次报告，逐步整理成机器可以记录、分析、复用、迁移和审计的焊接技能资产。

当前最重要的对象叫 WeldSkillPackage。可以把它理解为一个“焊接技能包”：里面记录这个技能来自哪里、适用于什么焊接任务、轨迹和姿态怎么表达、工艺参数是什么、哪些条件下可以迁移、哪里容易失败、机器人执行时需要哪些建议，以及证据状态是否可靠。

当前阶段

当前阶段是围绕 WeldSkillPackage 的第一阶段项目级重构。

过去一段时间里，项目陆续完成了 POC、MVP、资料 gate、输入规范 gate、仿真输出接入 gate 和报告机制。它们证明基础代码、数据结构和证据生成机制已经跑通。现在的工作不是否定这些成果，而是把项目从“报告和验证任务堆在一起”的状态，整理成“Physical AI 焊接技能资产底座”的状态。

这次重构要解决的主要问题是项目变得臃肿：入口文档里同时出现 POC、MVP、gate、场景计划、白皮书和报告命令，容易让读者误以为这些历史阶段就是当前研发主线。新的默认主线应当更清楚：本仓库服务 A02 焊接技能大师平台在 Physical AI 方向下的研发，核心资产对象是 WeldSkillPackage。

已完成

已经完成的基础能力包括：

  • 有可运行的 weldcore 代码引擎。
  • 有基础数据结构，可以表达 SkillDataset、焊接样本、WeldSkillPackage、迁移实验和评测证据。
  • 已跑通经验结构化 POC，证明焊接轨迹可以被拆解和重组。
  • 已跑通技能迁移 MVP，证明技能包可以在简化条件下迁移并被评测。
  • 已跑通资料底座、输入规范和仿真输出接入等 gate，证明资料、字段、仿真假设和导入证据可以被组织起来。
  • 已保留报告命令，用于生成当前证据或历史支撑材料。
  • POC、MVP、gate、白皮书和旧计划已经归档为历史证据和支撑机制，而不是继续占据默认项目入口。

这些成果说明软件和数据结构层面的最小闭环已经存在，但不能说明真实焊接质量已经验证。

当前工作

当前工作是减轻项目臃肿，把仓库结构和战略方向对齐。

具体来说：

  • 根目录入口改为 Physical AI 焊接技能资产底座。
  • 默认主线改为围绕 WeldSkillPackage 建立技能资产。
  • POC、MVP、gate 和报告命令保留，但放回“证据”和“历史支撑”的位置。
  • stiffened-panel-fillet 保留为历史资料 gate 和行业实例，不再作为默认项目主线。
  • simlite 保留为 L0 稳定仿真和测试工具，不被写成最终类机器人仿真方案。
  • ManiSkill/SAPIEN 只在独立 conda 环境里做本机小规模试跑，用来检查外部仿真任务能否接入项目数据结构，不作为当前基础依赖。

下一步

当前下一步已经从路线准备推进到最小仿真验证：先用两个核心 WeldSkillUnit 做对照试跑，并优先在独立 conda 环境运行 ManiSkill/SAPIEN 本机轻量任务，检查任务生成、运行记录和结果转换是否能走通。更细的任务、demo、raw artifact、adapter 和经验级数据证据说明放在 docs/simulation/ 中维护。

这意味着项目会继续回答三个问题：

  1. 一个 WeldSkillPackage 里面应该如何拆出更小、更可复用的 WeldSkillUnit。
  2. 类机器人仿真应如何读取、生成或验证这些技能资产。
  3. Rerun 如何作为证据回放和时间轴检查工具接入，但不承担仿真器角色。

下一步不是马上选择最终仿真器。最终仿真器需要在技能资产对象、adapter 边界、机器人约束和验证目标更清楚之后再评估。

尚未完成

当前仍未完成的能力包括：

  • 真实焊接质量验证：还没有把真实焊机、机器人、焊材、工艺参数、焊后检测和质量结果接成完整闭环。
  • WPS/PQR：当前资料、输入规范和仿真假设不能替代正式焊接工艺规程或工艺评定。
  • 最终仿真器选择：ManiSkill、SAPIEN、Isaac、ROS、MoveIt、Gazebo 等只能作为候选 adapter 或生态参考。
  • 完整业务平台：当前重点仍是技能资产、数据结构、证据边界和验证路径，不是完整业务系统页面。
  • 专家知识系统化录入：技能大师经验还需要后续形成稳定的采集、标注和审查格式。

最近一次验证方式

进入 weld-experience-engine 后运行：

uv sync --extra dev --extra viz
uv run pytest -q

报告命令仍可按需运行，用来生成当前证据或历史支撑材料；它们不是默认研发主线本身。

风险提醒

  • 不要把 stiffened-panel-fillet 写成当前默认项目主线。
  • 不要把 simlite 写成最终类机器人仿真路线。
  • 不要把 Rerun 写成仿真器、机器人控制总线或生产数据库。
  • 不要把外部仿真器或机器人生态写成项目核心对象；它们仍是候选或工业参考路线，不代表最终仿真器选择。
  • 不要把 ManiSkill/SAPIEN 最小闭环产物写成机器人可执行工艺包。
  • 不要把公开资料、合成数据、仿真输出或报告结论写成真实焊接质量验证。
  • 不要把资料证据、输入规范或仿真假设写成 WPS/PQR。
  • 不要删除历史成果；历史材料应继续保留在归档目录中。
